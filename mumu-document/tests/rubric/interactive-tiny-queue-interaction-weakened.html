tiny-queue의 구조와 동작

tiny-queue는 작업을 jobs.db 한 파일에 저장하고, 작업자가 가장 오래된 작업부터 하나씩 실행하며, 실패한 작업은 세 번까지 다시 시도해요.

파일은 여섯 개예요. 명령줄 입구인 cli.py, 작업을 다루는 queue/ 폴더, 웹 화면인 web/ 폴더, 그리고 데이터 파일 jobs.db로 나뉘어요.

저장

작업의 네 가지 상태

작업(job)은 queue/store.py가 jobs.db에 한 줄씩 기록해요. 작업마다 아래 상태 중 하나를 가져요.

  • 대기(pending): 아직 아무 작업자도 가져가지 않았어요.
  • 실행 중(running): 작업자가 가져가서 실행하고 있어요.
  • 완료(done): 문제없이 끝났어요.
  • 실패(failed): 실행하다 오류가 났어요.

작업 넣기

tq push <job>를 실행하면 cli.py가 새 작업을 대기 상태로 넣어요. 넣기만 하고 실행하지는 않아요. 실행은 작업자가 맡아요.

실행

작업자

tq work를 실행하면 queue/worker.py가 시작돼요. 작업자(worker)는 작업 하나를 이 순서로 처리해요.

  1. 가장 오래된 대기 작업을 하나 가져와요.
  2. 그 작업을 실행 중으로 바꿔요.
  3. 작업을 실행해요.
  4. 성공하면 완료로, 오류가 나면 실패로 바꿔요.

웹 화면

web/app.py는 Flask로 만든 페이지예요. 작업을 상태별로 나눠 보여 줘요. 멈춘 작업이 있는지 여기서 확인할 수 있어요. 멈춘 작업은 멈춘 작업 되살리기에서 설명해요.

실패 처리

실패한 작업 다시 시도하기

queue/retry.py는 실패한 작업을 다시 대기로 돌려놓아요. 한 작업에 최대 세 번까지만 해요. 세 번 모두 실패하면 그 작업은 계속 실패 상태로 남아요. 아래 그림은 7번 작업이 한 번 실패한 뒤 다시 시도해서 성공하는 과정이에요.

  1. 작업자가 가장 오래된 대기 작업인 7번을 가져와 실행 중으로 바꿔요.
  2. 실행하다 오류가 나서 작업자가 7번을 실패로 바꿔요.
  3. retry.py가 7번을 대기로 되돌려요. 첫 번째 재시도예요.
  4. 작업자가 7번을 다시 가져가 실행 중으로 바꿔요.
  5. 이번에는 성공해서 7번이 완료가 돼요.

멈춘 작업 되살리기

작업자가 실행 도중에 죽으면, 그 작업은 실행 중 상태로 계속 남아요. 다른 작업자는 대기 작업만 가져가므로 이 작업을 아무도 다시 실행하지 않아요. tq work --reset을 실행해야 이 작업이 대기로 돌아가요.

주의할 점이 두 가지 있어요.

  • 세 번 실패한 작업은 저절로 다시 실행되지 않아요.
  • 작업자가 죽어서 멈춘 작업은 재시도 대상이 아니에요. 실패가 아니라 실행 중 상태이기 때문이에요.
