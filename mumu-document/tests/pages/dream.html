다듬은 점

이슈에 올린 안보다 더 줄이고 더 안전하게 고쳤어요.

무엇을어떻게왜
여러 프로젝트에 걸친 교훈의 승격dream이 새 규칙을 만들지 않아요. lesson.md에 이미 있는 줄("다른 프로젝트 메모리에 이미 있으면 ~/.claude/CLAUDE.md로")을 그대로 써요.규칙을 두 번 적지 않아요.
적용 범위dream의 SKILL.md에 한 문장만 둬요. lesson.md의 '이 프로젝트'와 '이 세션'을 모든 메모리 폴더로 넓혀 읽으라는 문장이에요.심사에서 찾은 A안의 결함(lesson.md:16-17, :20)을 고쳐요.
네 가지 점검없는 파일을 가리키는 링크, 목차에 없는 파일, 같은 이름 두 개는 셸 명령으로 찾아요. 여러 폴더에 있는 같은 교훈만 모델이 판단해요.판단할 것만 모델에게 맡겨요.
두 스킬의 경계retro와 dream 설명에 서로를 "Not for"로 적어요(C안에서 가져옴).잘못된 스킬이 불리지 않아요.
작업 순서레이아웃과 교훈 전달을 동시에 진행하고, dream은 그 뒤에 해요.dream은 교훈 전달이 바꾸는 lesson.md 줄을 써요.
평가(eval)가짜 메모리 폴더를 격리된 곳에 만들어 돌려요.진짜 메모리를 건드리지 않아요.

dream이 하는 일

owner가 /dream을 입력할 때만 돌아요(disable-model-invocation: true). 훅이 없어서 평소 세션에는 비용이 들지 않아요. retro는 세션마다 교훈을 적고, dream은 쌓인 메모리를 한꺼번에 정리해요.

/dream
  모든 ~/.claude/projects/*/memory/ 점검
    ├─ 셸: 없는 파일 링크 · 목차에 없는 파일 · 같은 이름
    └─ 모델: 여러 폴더에 있는 같은 교훈
  찾은 게 없음 ──▶ "찾은 것 없음" 보고, 아무것도 안 씀
  찾음 ──▶ 표 제안 (작업 · 항목 · 이유)
            owner가 줄마다 승인
              승인된 줄: 백업 → 수정 → 되돌리는 명령 출력
              거절된 줄: 그대로 둠

백업은 ${CLAUDE_PLUGIN_DATA}/dream/<시각>/에 복사하는 한 줄이라 스크립트가 필요 없어요.

나머지 두 결정

플러그인 폴더 규칙.

규칙은 retro의 skill-authoring.md 폴더 절 한 곳에만 둬요. 이 저장소의 AGENTS.md는 그 절을 가리키기만 해요. retro는 모든 프로젝트에 설치되지만 AGENTS.md는 이 저장소에서만 읽혀서예요.

  • bin/: 다른 곳에서 이름만으로 부르는 명령
  • lib/: 스크립트들이 가져다 쓰는 모듈
  • 두 스킬이 함께 쓰는 스크립트: 한 스킬에 두고 다른 스킬이 링크해요. hook-authoring.md에서 이와 어긋나는 구절은 지워요.

다른 프로젝트에도 맞는 교훈.

교훈을 배운 저장소에 이슈를 먼저 열고, ~/.claude/CLAUDE.md에 그 이슈 링크가 붙은 한 줄을 적어요. 이 한 줄이 owner가 말한 비유적 "broadcast"예요. 모든 세션이 이 파일을 읽으니 mumu-team 없이도 결국 모든 프로젝트에 닿아요. GitHub 원격 저장소가 없으면 한 줄만 적어요.

작업 순서

순서작업난이도완료 기준 (실패할 수 있는 확인)
1retro: 플러그인 폴더 규칙낮음bin/과 lib/가 폴더 절에 있음 · grep -c "two skills" hook-authoring.md = 0 · AGENTS.md가 링크만 함 · 기존 eval 통과
1retro: 교훈을 이슈로 전달낮음eval spread: 모든 프로젝트용 교훈이 gh issue create를 실행함
2dream: 메모리 전체 정리보통eval dream: 심어 둔 중복이 제안되고, 고치기 전에 백업되고, 거절한 줄은 바이트 단위로 그대로 · eval dream-empty: 깨끗한 메모리면 "찾은 것 없음"이고 쓰기 없음

같은 순서 번호는 동시에 진행해요. 작업은 owner가 시작하라고 할 때 만들어요.
