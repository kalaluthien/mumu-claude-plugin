# contract

Write the findings as one contract the checker accepts and a blind reader can rebuild the subject from.

## Domain

A contract is one JSON object. Every record has an `id` of lowercase words joined by `-`, used once in the whole file, a source's and a level's included; a record names another only by its id, and a text names a node, an edge or an area as `{id}`, shown as that record's label; no other record has a label to show.

- **top**: `title`, `purpose`, `sources`, `terms`, `levels`, `areas`, `nodes`, `edges`, `scenarios`, `properties`, `questions`; the nodes, edges and areas are one list each for the whole subject, and a level is a view of them.
- **source**: `id`, `path` (a file under the subject's root, or a url), `says`, `authority` (what it outranks when two sources disagree). An `evidence` entry is a source id, `id:line` or `id:line-line`; nodes, edges, areas and properties take `evidence` and `basis` (`observed`, `documented` or `inferred`).
- **term**: `term`, `meaning`, `coined` when the subject made the word up.
- **level**: `id`, `title`, `about`. It shows the nodes and areas whose `level` names it and the edges that leave those nodes, one node at least. The first level is the whole subject.
- **node**: `id`, `label`, `tag`, `level` (the level that shows it), `area` (an area of the node's own level, or left out), `opens` (a level's id), `files` (the ids of the sources that are this node, where it is one or more files), `purpose`, `info`. A label is a noun phrase, such as "the checker".
- **edge**: `id`, `from`, `to`, `label`, `tag`, `many`, `info`; both ends sit on the edge's own level, and the id says what the edge does, such as `takes-items`, and holds neither end's id, so moving an end leaves it true. A static edge's label opens with a verb, so that `<from label> <label> <to label>` is a true and grammatical sentence, the label ending where the `to` label follows, such as "writes" or "takes its items from", whatever its tag: an `access` edge to a file reads "reads", "writes" or "appends a line to"; the checker refuses only a label of the wrong form (a capital first, a closing mark or article, a lone preposition, an end's label inside it), and the `read` call shows the writer whether the sentence is true, and it holds for one `to` unless `many` is true, which reads aloud as "each of" before the `to` label: set it only where one `from` relates to several of what the `to` node stands for. A `transition` edge joins two states; its label is the event, and `info` holds its `guard` and `action`.
- **area**: `id`, `label`, `tag`, `level`, `info`. An area tagged `region` holds the states of one thing, exactly one current, and names the first in `info.initial`; two regions of a level run side by side. A state answers each event of its region: a transition takes it, or its `ignores` item lists it as changing nothing, its `refuses` item as turned down, or its `terminal` item ends the lifecycle, and then no transition leaves it; `ignores` and `refuses` name an event by its transition's label, and an event that changes no state is listed in `ignores`, since an edge joins two different nodes.
- **info**: the items the element's tag fixes, each in its form: text, number, list, table (`{"columns": [...], "rows": [[...]]}`), tree (`[{"name", "note", "children"}]`) or code.
- **scenario**: `id`, `title`, `purpose`, `principle` (true for the story that shows the contract's purpose met), `steps`. A step is `{"at": <node or edge id>, "note": <60 characters at most>}`: the record it names says what happens.
- **property**: `id`, `kind` (`invariant`, `property`, `fact`, `gap`, `assumption`, `constraint` or `convention`), `strength` (`must`, `should` or `may`; `must` when left out), `status` (`holds`, `broken` or `unknown`; `holds` when left out), `statement`, `on` (ids). A `fact` names two `paths` of edge ids with one start and one end, which must agree; a `gap` names its `fault`, and its `status` is `unknown` when the sources do not settle it, `broken` when two of them disagree, and `holds` when the subject does it and no document says so.
- **question**: `id`, `asks` (one thing a reader must learn to rebuild the subject), then `answers` (the ids of the records that answer it, one at least with `evidence`) or `gap` (the id of the gap property that says why none does).

`${CLAUDE_PLUGIN_ROOT}/skills/system/examples/self/contract.json` is a whole one, of this skill; `${CLAUDE_PLUGIN_ROOT}/skills/system/examples/page-changes/contract.json` is a larger one, of a folder of code with eight levels.

## Steps

1. Copy the rebuild questions [extract.md](extract.md) wrote into `questions`, each with no answer yet.
2. Choose the levels: the whole subject first, with about five to twelve nodes, a deeper level as many as its question needs; open a node into a level only where a rebuild question lies inside it.
3. Write each node with its tag, purpose and the items of its tag; `python3 ${CLAUDE_PLUGIN_ROOT}/skills/system/scripts/check-contract.py tags` prints each tag's items and forms, and [tags.md](tags.md) says where each tag comes from and when a new one is earned. An item holds what the subject says, in its form: `terminal` holds what ends there, such as "the order is archived".
4. Write each relation as an edge, and each lifecycle as a region of states joined by transitions.
5. Write the scenarios as paths over those records, and the properties, gaps included.
6. Check: `python3 ${CLAUDE_PLUGIN_ROOT}/skills/system/scripts/check-contract.py check <contract> --root <subject root>` prints `ok`, or each break as `where: rule: message`; the `rules` call says what each rule asks.
7. Read aloud: the `read <contract>` call prints every edge as a sentence and every transition as `state -- event [guard] / action --> state`; correct each line that is false of the subject.
8. Ask the gaps: the `gaps <contract>` call prints what each topic holds and each open question; answer each from the sources by [extract.md](extract.md), or record a `gap` property `on` the record it names.
9. Score: `python3 ${CLAUDE_PLUGIN_ROOT}/skills/system/scripts/score-contract.py <contract> --root <subject root>` prints how many questions the contract answers and each quoted value its cited sources do not hold; correct the value or its evidence.
10. Sort the edges: `python3 ${CLAUDE_PLUGIN_ROOT}/skills/system/scripts/sort-edges.py <contract> --root <subject root>` prints each relation only the contract claims and each only the files show; add the edge, correct it, or record a gap.
11. Measure: give the contract alone to a fresh subagent and ask it what it would have to guess to rebuild the subject; each guess is a finding to add or a gap to record.

## Rules

- **One place per word**: a shown word sits in one record's `label`; every other record uses the id, so a rename changes one record.
- **No drawing**: the contract holds no position, colour, size or markup, in a field or in a text's words; the page's code decides them. A text that must quote the subject's own colour, length or style declaration puts it between backticks or in an item of the code form.
- **Catalogue apart**: an item's key in `info` is the catalogue's `name`, never shown; its shown name is the catalogue's `label`, so a new shown name changes `assets/tags.json` alone, and an item given another form changes the catalogue and the records that hold it, which `check <contract> --tags <file>` checks against a changed copy first, with `--root` beside it in either order; `statement`, `guard`, `action`, `initial` and `terminal` stay text and `ignores` and `refuses` lists, since the `read` and `gaps` calls read them so, and a catalogue that reforms one, in its tag or among the common items, renames one, or lacks a tag's `meaning` or an item's `label` or `example`, or holds a tag's items as other than a list of records, is refused; the catalogue fixes each item in one record, so a tag never fixes an item every element of its kind holds.
- **Add, never restate**: a new finding goes into the record it is about; a step's note never repeats what its record says, so it names neither end of its own edge.
- **Gaps stay**: an open question is answered or recorded with its fault, never dropped.
- **Narrowest gap**: a gap's `on` names the smallest record the question is about, since `gaps` asks nothing more of a record a gap names.
- **Name, never spell**: every text names a node or an area as `{id}` and never spells its label, so a new name changes the node's record alone, a level's and a scenario's title included, such as `Inside {server}`; an area is named so too; a label of a node or an area is two words or more, or the subject's own name of one word, such as `url.txt`, since no check can tell one common word from prose, and it holds no other node's or area's label; an area's label opens in lower case, so it reads inside a sentence; words are matched whatever the space between them, and a plural or another spelling is the writer's to find; only a name (a label of a node or an area, the contract's title, a term), a source's own words, an item of the code form and the subject's own words quoted in backticks stay as written; the name shows with a capital where it opens the text or follows a full stop, unless its first word is the subject's own name, such as a file name.
- **One level each**: a node or an area names one level, the one whose question it answers, so moving it changes its record alone; another level names it in a text as `{id}`.
- **Angle words between backticks**: write a placeholder, a comparison or the subject's own markup between backticks, such as `` `<plugin>` ``, or in an item of the `code` form, which the page draws as written; outside them a `<` that opens a word, a slash, `!` or `?` is refused as markup, whatever the word, and so is a table cell or a tree note that is no text, and `{word}` that names no record.
