# compare-designs: the reader judges whole alternatives by looking, not by trusting a description
family: problem
elements: stem, option-exhibit, answer, rival

## Why it works
The reader must read each alternative as a person using it would, so a claim about the idea is tested on what the exhibit does, not on a label. It prevents option text that carries the answer in its adjectives (card-exhibit, card-rival).
The stem names the one judgement (which is fastest, clearest, safest to the person in the case); every option is a real design a competent person without the idea would ship (card-rival).

## Parts
- stem: asks for one judgement about the alternatives and names who is judging; no verdict words.
- option-exhibit: one rendered exhibit per option; `differs` names the single property that varies, everything else is identical.
- answer / rival: one text line naming the variant (never the verdict) plus a why; the weight sits in the why, which says what the exhibit does to the person in the case (card-why).

## Examples
Source book: the UX book (ids are its card or figure ids, with the unit in parentheses).
- probe-per-list (u-percept): three lists of the same six items, differing only in how the failed item is marked (sentence per row, colour on one badge, sort order). Essential content: the badge-only list wins; the other two force a row-by-row read.
- ask-per-split (u-percept): three action rows on one form, differing in how the destructive button is separated (gap, shared border, warning text). Essential content: a gap beats text because grouping is seen before words are read.
- ask-per-label (u-percept): three charts of the same series, differing in legend placement. Essential content: names attached to line ends need no matching.
Elsewhere: Three checkout pages that differ only in where the delivery fee first appears; the reader picks the one a shopper notices before paying.
# Compose and vary
- Combines with: near-miss (one option almost has the property), probe-before-reveal (as the opening probe), annotated-exhibit (marks inside each option).
- Vary: change the varied property and the judge (speed, error, trust, cost), keep the case fixed so the reader compares like with like. A new domain needs an exhibit that can be drawn, not described.
- Usual failure: options differ in two ways, so the right answer has two reasons and a rival is right for a hidden one (differs-one).

## Seed
Does each option differ from the others in exactly one named property, and can the reader answer from the exhibits alone?
